Architecture:
1. Android Folder Agent opens DeepSeek or Claude in an Android WebView using the owner’s signed-in web session.
2. It watches one SAF-selected shared folder for .txt prompt files and writes .response.txt replies to that same folder.
3. Termux runs bridge.py, authenticated through GitHub CLI, and polls a private GitHub Issues queue.
4. The bridge transfers issue text to the phone folder and posts the response back to GitHub.
5. In code mode, it validates a unified diff, applies it on an isolated codex/issue-N branch, commits/pushes, and creates a draft PR for human review.

Provider issue title prefixes:
[DeepSeek]       text request
[DeepSeek-Code]  code patch
[Claude]         text request
[Claude-Code]    code patch

Request body protocol:
DEEPSEEK-PHONE-BRIDGE/1

PROMPT:
<plain-text request>

The bridge adds a provider marker. The phone app must have that provider selected. It does not force provider tools, modes, model choice, or response length.

VERIFIED FROM SOURCE / OWNER EVIDENCE
- The Android app now has a one-folder prompts-and-replies selection.
- DeepSeek simple text exchange and one-folder response saving worked in the owner’s screenshots.
- A DeepSeek-generated diff was used to create a draft PR, which the owner says was merged.
- The app can select DeepSeek or Claude in source.
- The bridge requires an owner-authored issue in the private queue.
- Code requests require a separate clean code checkout on its default branch with a GitHub origin and configured Git author.
- The patch parser expects one unified Git diff, optionally inside a diff/patch fence; current parser strips known WebView toolbar labels.
- Patch limit is 1 MB. It rejects unsafe paths, binary patches, renames/copies, symlinks, and submodules.
- It never executes model/issue text as a shell command; it does not run tests or merge PRs.
- If a code patch or Git operation fails, the issue may remain open and the patch is held for review.
- Phone app source attempts a send click and one Enter fallback, then detects a stable answer. It can hold requests when sending or completion is uncertain.
- The app must remain open and watching; Termux must remain running. Android background restrictions and GitHub connectivity can interrupt polling.
- Claude’s live WebView send/answer flow has not been verified on the owner’s phone.
