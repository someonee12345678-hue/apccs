The route currently works like this:
- A private GitHub Issues repository is the queue.
- A Termux poller uses `gh` to move owner-authored issue prompts to one shared phone folder and read the response file.
- The Android app opens the selected chatbot’s web interface in a WebView, submits the prompt, reads the finished reply, and saves it beside the prompt.
- Text issues receive a reply comment.
- Code issues request a unified diff; the bridge validates it, applies it on an isolated branch in the configured local code checkout, commits/pushes that branch, and opens a draft PR.
- It does not execute issue or chatbot text as commands, run tests, or merge code PRs.

Known limits:
- Claude has not yet been built and verified in the live phone WebView. Sign-in, prompt entry/send, response detection and saving still need a real phone check.
- The Termux poller and Android app must currently be running on the phone; Android may stop them. Do not describe the system as unattended or fully autonomous until that is actually solved and verified.
- The earlier smoke test used a clone of the bridge repo itself as `--code-repo`; it added `examples/hello_phone.py` to the bridge repo. That proved one patch path, but it did not prove a patch against a separate project.
- For future code work, keep the bridge repo separate from the target code repo. Do not assume a target project without checking the owner’s current instruction.
- No new chatbot request has been created or dispatched for this handoff.
